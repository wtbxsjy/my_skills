Task: `$@`

This skill packages the official **nf-core agent context file** from
https://github.com/nf-core/agents (`resources/pipeline/AGENTS.md`, MIT, repo commit `9ccb6b2`) so it can be
applied on demand. The complete, unmodified file is in `references/AGENTS.md`: **read it before changing an
nf-core pipeline** and follow it; the summary below only lists the rules that most often decide success.
If the pipeline repository already has its own `AGENTS.md`, that file wins.

## Step 1 — Confirm this is an nf-core pipeline

```bash
test -f nextflow_schema.json && ls modules/nf-core subworkflows 2>/dev/null | head
git branch -a | grep -E 'TEMPLATE|dev|main|master'
```

- Not an nf-core pipeline → stop; use the generic Nextflow skills instead (see `nextflow-skills-guide`).
- Old DSL1 pipeline (single file, `Channel.from`) → **do not work on it**.

## Step 2 — Rules that most often matter (MUST / MUST NOT)

Structure and files
- Files that do not match the template tree (`conf/`, `main.nf`, `modules/{local,nf-core}`, `subworkflows/{local,nf-core}`,
  `tests/default.nf.test`, `workflows/<name>.nf`) → **ask the user before editing**. Do not add files to `workflows/`.
- **Never edit** `base.config`, `igenomes.config`, `igenomes_ignored.config`. Module arguments go in `modules.config`
  (`withName` blocks) via `ext.args` / `ext.prefix`.
- Do not hand-write anything nf-core tools generates; if an `nf-core` command fails, ask the user.
- Prefer existing nf-core modules/subworkflows; do not edit them in place (if unavoidable: edit `main.nf` only,
  run `nf-core modules patch <name>`, and flag that an upstream PR is needed). Module names use a slash: `samtools/sort`.
- The meta map must contain a unique `id`; nf-core modules may read only `id` and `single_end`; channel operations
  must preserve the meta map.
- Publish outputs the same way the pipeline already does (workflow outputs vs `publishDir`).

Testing
- At least one nf-test case per pipeline; run with `nf-test test <path>`. **Never edit snapshots by hand**; refresh
  with `nf-test test --profile +<docker|singularity|conda> --update-snapshot` and only on the CI CPU architecture.
  Unstable outputs go into `.nftignore`.

Git, commits, push, PR
- **Never** switch to or write to `TEMPLATE`; never write to `main`; do not commit feature work directly to `dev`.
  Branch per feature, PR to `dev`.
- After editing Nextflow files run `nextflow lint -format`. Before each commit stage changes and run `prek`; before
  pushing run `nf-core pipelines lint` (`--release` for a PR to main) and `nf-test test tests/`.
- **Ask the user before pushing.** Never force-push (`--force-with-lease` only after rewriting history).
- PRs: one feature, follow the PR template checklist, add a CHANGELOG.md line.
- Self-disclosure: if you wrote most of a commit, end the commit body with `Generated by <your name>`; for a PR you
  open autonomously, put the same line at the end of the PR message above the checklist.

Writing style
- English with British spelling; short declarative sentences; no em-dashes or non-ASCII decoration; comments
  explain *why*, not *what* (default: no comment). Do not "correct" tool names, flags or package names.

## Step 3 — Offer to install the file into the pipeline

If the user wants every agent that touches the repository to follow these rules, copy it to the pipeline root:

```bash
cp <this-skill-dir>/references/AGENTS.md ./AGENTS.md
```

Agents that read `CLAUDE.md` instead can import it with a one-line `CLAUDE.md` containing `@AGENTS.md`. The upstream
file is meant to be updated by nf-core core members, so prefer copying a fresh version from
https://github.com/nf-core/agents rather than editing the copy; put project-specific rules in a separate section
or file.
